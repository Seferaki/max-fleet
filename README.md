# MAX Fleet

Служебный автопарк в MAX: сотрудник бронирует машину, фиксирует состояние до поездки и после неё, а администратор получает историю и замечания.

## Доступ и версия для сдачи

- [Бот MAX Fleet — открыть в MAX](https://max.ru/se14505137_bot).
- [HTTPS мини-приложения](https://185-146-157-147.sslip.io/). Карта требует запуска из MAX с подписанным контекстом и действующим возвратом.
- [Репозиторий](https://github.com/Seferaki/max-fleet). Для сдачи используется постоянная ссылка на конкретный коммит; полный SHA текущей версии: `git rev-parse HEAD`. После дедлайна сдаваемый SHA не заменяется.
- [Состояние реализации и опубликованные проверки](docs/progress/BACKEND.md).

На сервере установлен доверенный TLS-сертификат Let's Encrypt, gateway запущен, подписка webhook MAX зарегистрирована и проверена повторным запросом API. **Полный сценарий в приложении MAX ещё не подтверждён:** остаются настройка Mini App в кабинете владельца, регистрация реального тестового MAX ID и проверка фото/карты с устройства. Контейнерный стенд и синтетические проверки не заменяют эту проверку.

## Основной пользовательский сценарий

1. Сотрудник выбирает доступный автомобиль. Бронь удерживается **15 минут**; сотрудник проходит проверочный пример и принимает правила.
2. Указывает пробег, топливо и состояние автомобиля, загружает **8 фото до поездки**, подтверждает начало.
3. При возврате указывает пробег, топливо, состояние, закрытие машины и наличие ключей; загружает **8 фото после поездки**.
4. В мини-приложении вручную выбирает место парковки и подтверждает возврат. Разрешение GPS необязательно.
5. После безопасного завершения автомобиль снова доступен. Администратор работает с замечаниями, историей и при необходимости выполняет подтверждённое аварийное закрытие поездки.

## Архитектура

| Компонент | Ответственность |
|---|---|
| Go gateway | MAX webhook, диалоги, внешний API карты, проверка подписи MAX и отправка уведомлений |
| React / TypeScript | Обязательный экран ручного выбора парковки |
| Python Data API и worker | Бизнес-инварианты, транзакции, SQL, миграции, метаданные фото и очереди |
| PostgreSQL | Данные; доступ к SQL имеет только Python |
| SeaweedFS S3 | Приватные файлы фотографий локального стенда |
| Nginx | Web и проксирование к gateway; на VDS — HTTPS с TLS |

Go обращается к Python по [OpenAPI 1.13](contracts/data-api.openapi.yaml), не подключается напрямую к PostgreSQL или S3. Полный Docker-стенд использует настоящий Python API; отдельный Go mock сохранён для изолированной разработки.

## Зависимости и Docker-конфигурация

Для запуска нужны Docker Engine / Docker Desktop с Linux containers и Docker Compose **2.20+**, интернет для загрузки базовых образов и браузер. Go, Python и Node.js на хосте для запуска Compose не требуются.

- [compose.yaml](compose.yaml) включает [полный стек](deploy/compose.full.yaml) и его Data API конфигурацию.
- Dockerfile: [Go](services/gateway/Dockerfile.gateway), [Python](services/data/Dockerfile), [React web](web/Dockerfile).
- [.dockerignore](.dockerignore); отдельные `.dockerignore` также лежат в build contexts компонентов.
- [.env.example](.env.example) содержит примеры без рабочих токенов, паролей и ключей.
- Версии зависимостей: [go.mod](services/gateway/go.mod), [go.sum](services/gateway/go.sum), [uv.lock](services/data/uv.lock), [package-lock.json](web/package-lock.json). Базовые образы закреплены в Dockerfile/Compose.

Сборки используют кеш слоёв и зафиксированные зависимости. Требование сборки за 5 минут без первоначального скачивания базовых образов **в этой сдаче не замерялось**; результат по времени не заявляется.

## Подготовка окружения и запуск

Один раз скопируйте `.env.example` в `.env` и создайте секреты вне репозитория. PowerShell:

```powershell
Copy-Item .env.example .env
$env:MAX_FLEET_SECRETS_DIR = 'C:\MAXFleet\secrets'
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/bootstrap.ps1
```

Linux/macOS:

```bash
cp .env.example .env
export MAX_FLEET_SECRETS_DIR="$HOME/.local/share/max-fleet/secrets"
bash scripts/bootstrap.sh
```

**Одна команда запуска всех локальных компонентов** из корня репозитория:

```bash
docker compose --env-file .env -p max-fleet-demo up -d --build --wait
```

Запускаются PostgreSQL, S3, миграции, Python API/worker, Go gateway и React web. Откройте `http://127.0.0.1:8081`. Открытие карты вне MAX не даёт авторизации: нужен подписанный контекст MAX и текущий возврат.

### Параметры окружения

| Переменная | Назначение / локальное значение |
|---|---|
| `APP_ENV` | `development` для локальных тестовых данных; `production` для live |
| `SEED_SYNTHETIC` | `1` загружает синтетический seed; в production обязательно `0` |
| `MAX_FLEET_SECRETS_DIR` | Закрытый каталог секретов вне Git; для Windows Docker рекомендуется ASCII-путь |
| `MAX_UPDATE_MODE` | `disabled` локально; `webhook` для подключения MAX |
| `MAX_INTEGRATION_KEY` | Идентификатор подключения; локально `demo-bot` |
| `PUBLIC_BASE_URL` | Публичный HTTPS origin для live; локально может быть пустым |
| `WEB_PORT`, `DATA_API_PORT` | Порты хоста: `8081`, `18000` |
| `COMPANY_MAP_LAT`, `COMPANY_MAP_LON` | Центр карты; обязателен в production |
| `COMPANY_TIMEZONE` | Часовой пояс компании, например `Europe/Moscow`; обязателен в production |
| `MAP_TILE_URL`, `MAP_ATTRIBUTION` | Источник тайлов и обязательная подпись карты; по умолчанию OpenStreetMap |
| `MAX_BOT_NAME` | Публичный username бота для ссылки на карту |
| `MAX_PHOTO_HOSTS` | Проверенные точные HTTPS hostname CDN MAX; до настройки реальные фото не обрабатываются |
| `S3_BUCKET`, `S3_REGION` | Приватное хранилище фото: `max-fleet-photos`, `us-east-1` |

Сервисные токены, пароли PostgreSQL и ключи S3 создаёт bootstrap и передаёт контейнерам файлами Docker secrets. Реальные MAX token и webhook secret также хранятся в приватных файлах. Значения секретов не публикуются. Подробности и имена файлов: [OPERATIONS.md](docs/OPERATIONS.md).

### Порты

| Адрес / порт | Доступ и назначение |
|---|---|
| `127.0.0.1:8081` | Web и gateway через proxy; только локальный хост |
| `127.0.0.1:18000` | Python Data API для локальной диагностики |
| `gateway:8080`, `data-api:8000` | Внутренняя сеть Compose |
| PostgreSQL `5432`, S3 `8333` | Внутренняя сеть; не опубликованы на хост |
| VDS `443`, `80` | HTTPS вход и обслуживание TLS/HTTP redirect |

## Внешние сервисы и условия проверки MAX

MAX нельзя воспроизвести внутри Docker. Для проверки в мессенджере нужны учётная запись владельца бота, действующий MAX token, доступный HTTPS origin и активная webhook-подписка. На VDS TLS и подписка уже настроены; сервисы оставлены работающими.

Владелец открывает [MAX для бизнеса](https://business.max.ru) → «Чат-боты» → MAX Fleet → настройки, сохраняет URL Mini App `https://185-146-157-147.sslip.io/` и кнопку запуска. Затем открывает бота в MAX. Для полного сценария реальный MAX ID должен быть приватно зарегистрирован как сотрудник/администратор; фиктивные IDs из seed не предоставляют доступ реальным пользователям MAX. Первого администратора создаёт Python `bootstrap-admin` из приватного `BOOTSTRAP_ADMIN_MAX_ID_FILE`.

Для тайлов карты нужен доступ браузера к настроенному tile-сервису OpenStreetMap. Для реальных фото нужны доступ к CDN MAX и точный allowlist `MAX_PHOTO_HOSTS`. Публичный origin сейчас использует временный DNS alias `sslip.io`; сертификат действителен до 29.12.2026, автоматическое продление включено. Data API доступен внутри сети, отдельный публичный API для сторонних клиентов не предоставляется.

## Работа с данными

PostgreSQL хранит сотрудников и их права, автомобили, брони, поездки, осмотры, замечания, версии и данные повторов команд. Файлы фото находятся в приватном S3, метаданные — в PostgreSQL. Все изменения выполняет Python через API и транзакции. Идемпотентность и версии защищают от повторного выполнения и устаревших действий.

Миграции выполняются перед запуском API. Данные сохраняются в named volumes и переживают обычный `stop`/`down`. Production и demo используют разные volumes. [Политики MVP](docs/policies/README.md) описывают доступ и хранение; автоматическое удаление по срокам и расписание backup ещё не настроены.

### Тестовые данные

При `APP_ENV=development` и `SEED_SYNTHETIC=1` загружается [синтетический seed](services/data/fixtures/synthetic-seed.json): 10 машин, 4 сотрудника (`driver-1`, `driver-2`, `admin-1`, `blocked-driver`), правила и интеграция. Seed идемпотентен, не очищает данные и сам не создаёт историю поездок. Это фиктивные MAX ID без паролей.

На отдельном demo-стенде VDS ранее проверены 10 доступных машин, 4 сотрудника и одна завершённая синтетическая поездка с 8+8 тестовыми фото и `manual_map`. Production работает с `SEED_SYNTHETIC=0`. В [наборе фото](docs/demo/vehicle-inspections/README.md) есть 33 AI JPEG; они не загружаются автоматически. Контрактный smoke использует отдельные технические PNG 1×1, которые не являются фотографиями реальной поездки.

## Пошаговая проверка и ожидаемое поведение

### Локальная проверка без MAX

1. Подготовьте окружение и запустите Compose указанной выше командой. Ожидается запуск всех сервисов; gateway healthcheck подтверждает liveness, worker — наличие процесса.
2. Откройте `http://127.0.0.1:18000/health/ready`: ожидается HTTP 200. `http://127.0.0.1:8081/health/ready` возвращает `static_ready`.
3. Для API-сценария на свежем синтетическом стенде установите `uv` и выполните из корня в PowerShell:

```powershell
$env:MAX_FLEET_SECRETS_DIR = 'C:\MAXFleet\secrets'
$env:DATA_API_URL = 'http://127.0.0.1:18000'
uv run --project services/data python services/data/scripts/smoke.py
```

Smoke изменяет тестовую БД: создаёт бронь, подтверждает пример/правила, сохраняет 8+8 фото, ручную парковку и завершает поездку. Ожидаются завершённая поездка, доступный автомобиль и сохранённый последний осмотр. Запускайте только на выделенном синтетическом стенде; это не проверка клиента MAX.

### Ручной сценарий в MAX после настройки аккаунта

| Шаг | Ожидаемый результат |
|---|---|
| Открыть бота и нажать «Начать» зарегистрированным сотрудником | Доступ к меню согласно роли; неизвестному пользователю доступ не предоставляется |
| Выбрать свободную машину, решить пример и принять правила | Бронь на 15 минут, машина недоступна другим сотрудникам |
| Внести топливо/пробег, загрузить 7 фото, затем восьмое | Неполный комплект не позволяет начать поездку; полный комплект можно подтвердить |
| Подтвердить начало, затем открыть возврат | Активная поездка и форма возврата |
| Загрузить 8 фото после, подтвердить замок/ключи и ручную точку карты | Готовность к безопасному завершению |
| Подтвердить возврат, повторить ту же операцию | Одна завершённая поездка; повтор не создаёт дубликат |
| Проверить историю и замечание администратором | Доступ по роли; аварийное закрытие требует административного подтверждения |

При меньшем пробеге ожидается `ODOMETER_ROLLBACK`; при конфликте версии — отказ устаревшему действию. Ошибка фото не должна давать ложное подтверждение загрузки. Небезопасный возврат не освобождает автомобиль как исправный; предусмотрен административный разбор.

## Известные ограничения

- Полный сценарий настоящего MAX, Bridge, фото-CDN и ручная карта на устройстве ещё не приняты; Mini App и реальная учётная запись требуют действий владельца.
- QA пропущена по решению владельца, статус **NOT RUN**. При подготовке финального README новые тесты и сборки не запускались.
- Длительность сборки ≤5 минут не подтверждена замером.
- Автоматические retention и регулярный backup не настроены; политики требуют утверждения оператора перед использованием персональных данных.
- Синтетический API smoke и доступность HTTPS не доказывают прохождение основного сценария в MAX.

## Остановка и повторный запуск

```bash
docker compose --env-file .env -p max-fleet-demo stop
docker compose --env-file .env -p max-fleet-demo start
```

Пересборка после обновления:

```bash
docker compose --env-file .env -p max-fleet-demo up -d --build --wait
```

Удалить контейнеры и сеть, сохранив данные:

```bash
docker compose --env-file .env -p max-fleet-demo down
```

Не добавляйте `-v`, если данные должны сохраниться. Для нового чистого тестового набора используйте отдельное имя Compose project и свободные `WEB_PORT`/`DATA_API_PORT`.
