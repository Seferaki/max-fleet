# MAX Fleet

MAX Fleet помогает организациям с общим автопарком выдавать машины сотрудникам и фиксировать состояние автомобиля до поездки и после неё. Основной интерфейс — чат-бот MAX; для ручного выбора места парковки используется подключённая мини-карта.

## Для кого и какую задачу решает

Приоритетный пользователь — сотрудник компании с небольшим или средним общим автопарком, который получает автомобиль по рабочей задаче; второй пользователь — администратор автопарка. Когда выдача, пробег, топливо, фотографии и место возврата распределены по чатам и таблицам, сложнее установить состояние машины и ответственного за поездку. MAX Fleet собирает эти действия и историю в одном процессе.

Это продуктовая гипотеза для пилота, а не результат проведённого исследования: проверять её следует на фактических поездках. Ожидаемый эффект измеряется временем выдачи/возврата, долей поездок с полным комплектом осмотра и числом случаев, когда администратору приходится отдельно выяснять состояние автомобиля. Измеренные значения пока не заявляются.

## Основной пользовательский сценарий

1. Сотрудник открывает бота MAX, выбирает доступную машину и подтверждает правила. Машина удерживается за ним на 15 минут.
2. До начала поездки сотрудник указывает топливо и пробег, отвечает на вопросы о состоянии и загружает 8 обязательных фотографий.
3. После подтверждения поездка начинается. При возврате сотрудник фиксирует топливо, пробег, комплектность ключей и замок, состояние салона и машины, загружает ещё 8 фотографий и выбирает место парковки вручную на карте. GPS-разрешение необязательно.
4. После подтверждения возврата автомобиль безопасно становится доступен следующему сотруднику. Замечание можно приложить к поездке; администратор видит историю, назначает исполнителя и при необходимости закрывает активную поездку с подтверждением известных данных.

## Состав и архитектура

| Компонент | Назначение |
|---|---|
| Go gateway | MAX webhook и события, диалоги, проверка MAX-контекста карты, внешний API и уведомления. До подключения MAX gateway может работать в режиме `disabled`. |
| React / TypeScript Mini App | Экран ручного выбора и подтверждения точки парковки; отправляет подписанный контекст MAX в Go. |
| Python Data API и worker | Все бизнес-инварианты, транзакции и SQL, миграции, фотографии, очереди и интеграционные события. |
| PostgreSQL | Основные данные; доступ к БД имеет только Python-сервис. |
| SeaweedFS S3 | Локальное приватное хранилище фотографий в демонстрационном Compose. |
| Nginx / TLS | На сервере принимает HTTPS и проксирует запросы к web/gateway на loopback. |

Версии согласуются через [OpenAPI-контракт](contracts/data-api.openapi.yaml) версии 1.13. Go не подключается к PostgreSQL или S3 напрямую. В локальном полном Compose используется Python API, а не Go mock.

## Локальный запуск полного synthetic-стенда

Нужны Docker Engine и Docker Compose v2, доступ к сборке образов и браузер. Реальный токен MAX для локального стенда не нужен.

Скопируйте пример настроек и создайте локальные секреты. Каталог секретов должен находиться вне репозитория и синхронизируемых папок. Пример для PowerShell:

```powershell
Copy-Item .env.example .env
$env:MAX_FLEET_SECRETS_DIR = Join-Path $env:LOCALAPPDATA 'MAXFleet\secrets'
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/bootstrap.ps1
```

Запустите все компоненты одной командой из корня репозитория:

```powershell
docker compose --env-file .env -f deploy/compose.full.yaml -p max-fleet-demo up -d --build --wait
```

Откройте `http://127.0.0.1:8081`. Страница карты требует действительный подписанный контекст MAX и идентификатор возврата, поэтому обычное открытие URL в браузере подтверждает доступность web-контейнера, но не заменяет запуск карты из чата MAX.

Compose поднимает Go gateway, React web, Python API и worker, Alembic migration, PostgreSQL и S3. Сервисы готовы, когда Compose сообщает healthy для gateway, web, data-api, PostgreSQL и S3; одно лишь состояние контейнера gateway проверяет его liveness, а не завершённость всех диалогов.

### Переменные и секреты

Безопасные значения по умолчанию хранятся в [.env.example](.env.example). Основные настройки полного стенда:

| Переменная | Назначение | Локальный пример |
|---|---|---|
| `APP_ENV` | Режим приложения | `development`; обязателен для синтетического seed |
| `SEED_SYNTHETIC` | Загрузить тестовые записи при миграции | `1`; запрещено в `production` |
| `MAX_UPDATE_MODE` | Получение событий MAX | `disabled` для локального стенда; `webhook` для отдельного live-контура |
| `MAX_INTEGRATION_KEY` | Ключ подключения MAX в данных | `demo-bot` для синтетических примеров |
| `WEB_PORT` | Loopback-порт web на хосте | `8081` |
| `DATA_API_PORT` | Loopback-порт Python API на хосте | `18000` |
| `MAP_TILE_URL`, `MAP_ATTRIBUTION` | Тайлы карты и подпись источника | OpenStreetMap; значение и attribution показываются пользователю |
| `COMPANY_MAP_LAT`, `COMPANY_MAP_LON` | Необязательный центр карты | Пустые значения допустимы |
| `MAX_BOT_NAME`, `MAX_PHOTO_HOSTS` | Имя бота и разрешённые хосты медиа | Пустые в синтетическом режиме; задать для live-подключения |
| `S3_BUCKET`, `S3_REGION` | Настройки хранилища | Внутренний bucket `max-fleet-photos`, регион `us-east-1` |
| `MAX_FLEET_SECRETS_DIR` | Путь к приватным файлам секретов, задаётся в оболочке | `$env:LOCALAPPDATA\MAXFleet\secrets` |

`bootstrap.ps1` создаёт случайные локальные секреты сервисов, PostgreSQL и S3; он не создаёт MAX bot token и не добавляет секреты в `.env`. Для настоящего MAX используются приватные файлы `max_bot_token` и `max_webhook_secret`, TLS и внешний HTTPS reverse proxy. Не помещайте значения секретов в Git, README, презентацию или чат.

### Порты и внешние зависимости

| Адрес/порт | Доступ | Компонент |
|---|---|---|
| `127.0.0.1:8081` | Хост, loopback | React web |
| `127.0.0.1:18000` | Хост, loopback | Python Data API |
| `gateway:8080` | Только Compose network | Go gateway |
| `data-api:8000` | Только Compose network | Python Data API |
| PostgreSQL `5432`, S3 `8333` | Только Compose network | Не публикуются на хост |

Зависимости зафиксированы в `services/gateway/go.mod`/`go.sum`, `web/package-lock.json` и `services/data/uv.lock`; Docker-образы и версии PostgreSQL зафиксированы в Docker-конфигурации. В live-режиме внешние зависимости — платформа MAX и её HTTPS API. Для отображения карты браузеру нужен настроенный tile-сервис; по умолчанию указан OpenStreetMap. В локальном стенде фотографиями управляет Python, S3 реализует SeaweedFS.

### Тестовые данные и проверка

При первом запуске с `APP_ENV=development` и `SEED_SYNTHETIC=1` миграция загружает из `services/data/fixtures/synthetic-seed.json` 10 демонстрационных машин, 4 тестовых сотрудника, правила и тестовую запись интеграции. Seed идемпотентен: повторный запуск добавляет отсутствующие записи и не очищает изменения. В текущем локальном полном стенде данные проверены через Python API: доступны 10 машин, 4 сотрудника и текущие правила при `contract_version=1.13`.

В `docs/demo/vehicle-inspections/` лежат 33 синтетических кадра для двух машин: по 8 ракурсов до и после поездки и один дополнительный кадр замечания. Эти файлы не загружаются в БД/S3 автоматически; набор предназначен для ручной проверки загрузки фотографий. Персональные данные и реальные автомобили в seed не используются.

Для воспроизводимой проверки Python API используйте отдельный свежий Compose project с `SEED_SYNTHETIC=1`, затем из корня репозитория выполните в PowerShell:

```powershell
$env:MAX_FLEET_SECRETS_DIR = Join-Path $env:LOCALAPPDATA 'MAXFleet\secrets'
$env:DATA_API_URL = 'http://127.0.0.1:18000'
uv run --project services/data python services/data/scripts/smoke.py
```

Smoke использует локальные service-token файлы, не печатает их и проходит через Python API, PostgreSQL и S3: оформление, challenge, правила, 8 фотографий до, начало поездки, 8 фотографий после, ручную точку карты и завершение возврата. Ожидаемый результат — завершённая поездка, доступный автомобиль, сохранённый предыдущий осмотр и уведомления. Smoke изменяет тестовую БД; запускайте его только на синтетическом стенде. Он не является проверкой MAX webhook или MAX Mini App.

## Состояние реализации и ограничения

На 30.09.2026 опубликованный integration checkpoint содержит синтетический Go → Python → PostgreSQL/S3 путь; локальная БД этого стенда проверена на 10 машинах, 4 сотрудниках и правилах. MAX API `/me` проверен отдельным live-запросом без вывода токена. Полный пользовательский сценарий в реальном MAX и mini-app ещё не принят; `QA` намеренно пропущен по решению владельца и имеет статус **NOT RUN**, а не PASS. В отчёте проверки следует отличать реальные API-запросы от synthetic MAX events и данных.

Для пилота с реальными сотрудниками нужны настроенный HTTPS/webhook и Mini App в аккаунте MAX, приватно заданный ID первого администратора, реальные сведения об автопарке и утверждённые сроки хранения персональных данных/фотографий. Не запускайте synthetic seed в production и не подключайте к публичному серверу demo-volume.

## Остановка и повторный запуск

```powershell
docker compose --env-file .env -f deploy/compose.full.yaml -p max-fleet-demo down
```

`down` останавливает и удаляет контейнеры сети, но сохраняет named volumes PostgreSQL/S3. Для повторного запуска используйте команду `up` выше. Не добавляйте `-v`, если намеренно не удаляете все локальные тестовые данные и фото. Чтобы получить чистый набор, используйте новое имя Compose project и свободные порты.
