# Промпт запуска и продолжения backend

Откройте локальный клон репозитория в Codex на текущем ноутбуке и вставьте текст ниже. Можно добавить «этот ноутбук A» или «этот ноутбук B». Не вставляйте токены. При переходе после аварии явно укажите, остановлен ли старый исполнитель.

```text
Продолжи реализацию MAX Fleet в этом репозитории.

Сначала прочитай AGENTS.md, README.md, docs/IMPLEMENTATION_PLAN.md,
docs/HANDOFF.md и docs/progress/BACKEND.md. Проверь remote/ветку, git status,
последние commits и опубликованный checkpoint. Не полагайся на старую историю чата.

Действуй как текущий единственный backend-исполнитель. Если очередь FREE/HANDOFF,
захвати её claim-коммитом и обычным push до изменения кода. Если ACTIVE у другого
ноутбука, не начинай параллельную работу; нужен подтверждённый handoff/takeover
по docs/HANDOFF.md. Не применяй force push, reset --hard и удаление чужой работы.

Выбери ближайшую готовую задачу S/BE/UI из плана, с учётом зависимостей.
Реализуй маленькими проверяемыми шагами, проверяй результат и продолжай следующие
готовые задачи в рамках доступного сеанса. Не останавливайся после одного плана.
Статус DONE ставь только после фактических проверок и опубликованных артефактов.

Архитектура фиксирована: Go обслуживает MAX/диалоги/внешний API. Весь SQL и
бизнес-транзакции реализует отдельный Python-сервис data engineer.
До INT Go использует mock HTTP API по contracts/data-api.openapi.yaml.
Не подключай Go напрямую к PostgreSQL, не редактируй работу data engineer
без задачи интеграции. Если OpenAPI ещё нет, сначала выполни S-02.
Обязательный React-экран карты входит в UI-01 и не исключается из P0.

Проверяй auth/права, идемпотентность, версии, ошибки фото и восстановление.
Сохраняй пользовательские требования 8+8 фото, hold 15 минут, manual map,
безопасный возврат и admin close. Не объявляй mock доказательством готовности MAX.

Автоматизируй настройку, код, тесты и документацию. При недостающем действии
в аккаунте человека используй HUMAN_REQUIRED из docs/OPERATIONS.md: объясни
причину, дай точные минимальные шаги и ссылку. Пока возможно, делай независимую работу.
Токены не запрашивай в чате: подготовь скрытый локальный ввод или приватный файл,
проверь наличие/работоспособность без вывода секрета.

После каждого проверяемого подшага сохраняй code commit, затем обновляй
docs/progress/BACKEND.md с его SHA, командами, результатами, next_step и push.
Не жди предполагаемого конца лимита. Если остановка близка, выполни handoff.
Если произошёл сбой, честно пометь WIP/непройденные проверки.
Перед каждым push проверь владельца очереди и секреты в staged diff.

В финальном сообщении укажи: что реально реализовано, что проверено, checkpoint
и следующий шаг, состояние очереди, только необходимое действие человека.
Не утверждай, что изменения переданы другому ноутбуку, если push не подтверждён.
```

Для плановой передачи можно отправить отдельное короткое сообщение:

```text
Подготовь передачу работы следующему ноутбуку по docs/HANDOFF.md.
Заверши небольшой текущий подшаг или сохрани явно помеченный WIP.
Не начинай новую крупную задачу. Проверь секреты, сохрани код, результаты,
точный next_step и поставь HANDOFF. Подтверди успешный push.
```
