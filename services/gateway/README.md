# Go gateway и Data API mock

`cmd/gateway` обслуживает `/health/live` (200) и `/health/ready` (503). При настроенном `MAX_BOT_TOKEN_FILE` запускаются durable inbox worker и outbox notification sender; для очередей применяется отдельный `WORKER_API_TOKEN_FILE`. Go DataAPI client, WorkerClient и `cmd/data-mock` поддерживают чтение, hold на 15 минут, math take/return, правила, 8+8 фото, start/return, staged-фото замечаний, admin reads и durable inbox/outbox с claim/ack/retry. Inbox сверяет fencing token до команды; sender берёт только `recipient_max_user_id` из worker lease, отправляет через MAX SDK и подтверждает `provider_message_id`. Ошибки MAX получают exponential backoff 5/10/20/40 секунд; после пяти попыток или для неподдерживаемого события/невалидного адресата запись попадает в dead. Ответ MAX может быть принят, а подтверждение — потеряно, поэтому гарантия доставки at-least-once и возможен дубль после истечения lease. Mock хранит outbox вместе с доменной командой, проверяет lease и idempotency key, сохраняет snapshot/assets на диске; polling integration marker продвигается только после durable inbox. Sender пишет безопасные operation/request_id/error_code, счётчики claimed/sent/retried/dead/errors и возраст старшей delivery в claimed batch; actor/recipient, причины, payload, lease ID и секреты не логируются. `/health/ready` остаётся 503 как признак неполной реализации. `APP_ENV=production` запрещает запуск mock. Python и реальный MAX не проверялись; mock не доказывает их готовность.

Версия Go фиксируется в `go.mod`; официальный SDK MAX закреплён на `v2.4.1`. Проверки из этого каталога: `go test ./...`, `go vet ./...`, `go build ./cmd/gateway ./cmd/data-mock`. Для отдельного запуска mock задайте ровно один из `DATA_API_TOKEN` (только локальный dev) или `DATA_API_TOKEN_FILE` (приватный файл), отдельный `WORKER_API_TOKEN` или `WORKER_API_TOKEN_FILE`, а также `DATA_MOCK_SNAPSHOT_FILE` на постоянном томе. Совпадающие токены Data API и worker запрещены. Повреждённый snapshot блокирует старт вместо сброса к seed.

Compose для локальной разработки на Windows: из корня репозитория выполните `$env:MAX_FLEET_DATA_API_TOKEN_FILE = & powershell -NoProfile -ExecutionPolicy Bypass -File scripts/prepare-compose-token.ps1` и `$env:MAX_FLEET_WORKER_API_TOKEN_FILE = & powershell -NoProfile -ExecutionPolicy Bypass -File scripts/prepare-compose-token.ps1 -Name worker_api_token`, затем `docker compose -f deploy/compose.backend.yaml up --build -d`. Скрипт создаёт токены через bootstrap, если их нет, и копирует без вывода значений в игнорируемую `.local/compose-secrets/` с доступом только пользователя и Windows SYSTEM: Docker Desktop не смог смонтировать пользовательский файл из LocalAppData напрямую. На другой ОС задайте оба `MAX_FLEET_*_TOKEN_FILE` путями к разным приватным файлам самостоятельно. Для остановки без удаления snapshot: `docker compose -f deploy/compose.backend.yaml down`. Compose запускает один mock и gateway, публикует только gateway на `127.0.0.1:8080`, хранит snapshot/assets в `data_mock_state` и передаёт токены через Docker secrets. Healthcheck проверяет `/health/live`; `/health/ready` остаётся 503 до завершения mock и не является доказательством готовности MAX.
