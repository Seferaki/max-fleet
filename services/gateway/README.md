# Каркас Go

`cmd/gateway` пока обслуживает только `/health/live` (200) и `/health/ready` (503). `cmd/data-mock` обслуживает `/meta`, `/me`, `/state`, `/vehicles`, `/vehicles/{id}`, `/checkouts/{id}` и `/inspections/{id}` из синтетического seed и snapshot с проверкой service token, версии контракта и actor. Частично работают `checkout.create`, `checkout.cancel`, загрузка фото осмотра по слоту и `inspection.confirm_photos`: hold длится 15 минут, 8 слотов хранят метаданные в snapshot, файлы сохраняются приватно рядом с ним. Проверяются версия, hash, MIME, декодирование и размер; при ошибке записи ранее сохранённые слоты остаются. Подтверждение 7/8 возвращает недостающий слот. `/health/ready` остаётся 503: поездка, возврат и остальные команды ещё не реализованы. `APP_ENV=production` запрещает запуск mock.

Версия Go фиксируется в `go.mod`; официальный SDK MAX закреплён на `v2.4.1`. Локальные проверки после установки Go: из этого каталога `go test ./...`, `go vet ./...`, `go build ./cmd/gateway ./cmd/data-mock`. Для запуска mock задайте ровно один из `DATA_API_TOKEN` (только локальный dev) или `DATA_API_TOKEN_FILE` (предпочтительно, приватный файл), а также `DATA_MOCK_SNAPSHOT_FILE` на постоянном томе. Повреждённый snapshot блокирует старт вместо сброса к seed. MAX и Python-сервис пока не подключены.

DataAPI client формирует один multipart-запрос фото для выбранного слота и повторяет его с тем же Idempotency-Key после 503. Mock-проверки 8 фото проведены только для осмотра **до** поездки; 8 фото возврата и выдача содержимого assets ещё не реализованы.
