Сверено read-only с `origin/codex/data` commit `9eb2211b29e48fce8a6afc410bc986fa98a4988e` и его `docs/progress/DATA.md`; код Python здесь не менялся. Ветка Data использует contract commit `aa56f0e05b3c2458eee1fe88550d183ece9075af`/OpenAPI 1.0; текущий backend contract — v1.12, commit `a679941c1a9dac104502e41c5ffa10edb67fc7a4`. До INT Python должен синхронизироваться с v1.12; его тестовые и нагрузочные результаты не переобъявляются как общая приёмка.

Решения backend по вопросам DE:

1. `return.complete` возвращает `Return`, а завершённый Trip читается через `GET /trips/{id}`; это текущая backend-спецификация и mock. В schema результата указан общий union агрегатов, поэтому Python должен ориентироваться на operation mapping в API_CONTRACT, а не на старую v1.0 формулировку.
2. В текущей версии v1.12 фото явно повышает parent version; `inspection.update` и `inspection.confirm_photos` также меняют версию checkout/return в mock/Python. Документация API_CONTRACT теперь перечисляет все три операции. Wire shape/поведение не менялись, OpenAPI остаётся v1.12.
3. `RULES_REQUIRED` и `CHALLENGE_EXPIRED` — HTTP 422 по OpenAPI v1.12; текущий Go mock также отдаёт 422, Go-клиент ветвится по error code.
4. Не-admin GET `/admin/*` возвращает `403 ACCESS_DENIED`; admin-команды — `403 ADMIN_REQUIRED`.
5. Admin intent строго operation-specific: block — operation/target/version/reason; unblock добавляет review_completed; access — can_start_trip/reason; grant — target/version null плюс max_user_id/display_name; admin_close включает reason и available_data (обязателен даже `{}`). Proof возвращается как challenge_proof_id, финальная команда потребляет challenge_id и сверяет SHA-256 точного intent один раз. Это покрыто BE-09/mock тестами.
6. `conversation.save` адресован employee ID текущего actor; начальная версия черновика — 1, первое сохранение — версия 2.
7. Выдача доступа на MAX ID, уже существующий в реестре, — `409 INVALID_STATE`.
8. Recipient fan-out реализован в Go mock в BE-10/10.1: все admins; водитель для `trip_admin_closed`; affected employee для `access_changed` при grant и access change. `vehicle_blocked` создаёт admin event. BE-10 sender теперь доставляет очередь через MAX SDK; Python progress описывает тот же fan-out.
9. Previous-inspection photo route есть в OpenAPI, Go client и mock; ветке Data нужно перенести текущий маршрут вместе с v1.12.

Дополнительные замечания учтены в плане/коде: `ODOMETER_ROLLBACK` исправляется admin-аудитом odometer snapshot даже при активном hold/trip без изменения assignment/inspection/photos (BE-09); прирост строго более 1000 км требует подтверждения (BE-08); `assigned_to` сохраняет администратора, взявшего issue (BE-09). Категории `parking`/`car_lock` уже есть; один вопрос о закрытии+ключах предлагает четыре комбинации и записывает отдельные `keys_returned`/`car_locked`. Контакты не добавлены до H-03/H-04: нужен владелец, ACL, цель и срок хранения; `retired_at` остаётся P1 после P0. Hold остаётся 15 минут по прямому требованию. Для real pilot также нужно утвердить хранение фото/истории, backup ownership и удаление; персональные данные дальше не расширять до этого решения.

В `origin/codex/data` также опубликованы две правки общих backend-скриптов: `check-secrets.py` должен разрешать исходный код в `services/data/`, сохраняя запрет корневых runtime `data/`, а `bootstrap.ps1` поддерживает `MAX_FLEET_SECRETS_DIR` для ASCII-пути на Windows с кириллическим профилем. Ветка backend пока не содержит эти правки; перенести/проверить их отдельным подшагом перед общим чистым checkout/INT. Это не изменение `services/data/`.
