# Данные, доступ и сроки хранения

Статус: проект для будущего оператора; для demo/test использовать только синтетический набор. Сроки ниже — предложенные технические значения, а не установленная законом норма и не факт автоматического удаления в текущей версии.

## Какие данные затрагиваются

Система обрабатывает MAX user ID и отображаемое имя, роль/доступ сотрудника, идентификатор и регистрационное обозначение машины, поездки и осмотры, уровень топлива и одометр, замечания, точки ручного выбора парковки, фотографии и административные действия. Фото машины могут случайно содержать лица, номера или другие сведения о людях; геоточка парковки также может быть чувствительной в контексте сотрудника. Поэтому при реальном пилоте считать эти данные потенциально персональными.

В MVP не собирать телефон, домашний адрес, документы водителя, фоновые координаты, контакты из адресной книги или сведения, не нужные для поездки и разрешения замечания. Удалять их из скриншотов, логов и тикетов поддержки.

## Доступ

- Сотрудник видит доступный парк и собственный рабочий процесс; чужие сведения о водителе и неразрешённые фото ему не выдаются.
- Администратор получает только необходимые для автопарка действия. Изменение доступа, назначение исполнителя замечания, ручная коррекция показания и административное закрытие выполняются с авторизацией, проверкой роли и актуальной версии; чувствительные решения должны оставлять аудит.
- Изображения хранятся в приватном S3. Не публиковать bucket и постоянные ссылки, не печатать URL подписи, токены или содержимое фото в логах. Go обращается к Python Data API; PostgreSQL доступен только Python-сервису.
- Не использовать общие учётные записи для администраторов. Удалять/блокировать доступ бывшего сотрудника после подтверждения оператора. Контакты администратора выдаются только после предоставления реального и разрешённого контакта.

## Предложенные сроки для пилота

Эти сроки — конкретное начальное предложение MAX Fleet; оператор должен сверить их со своими целями и обязательными сроками хранения до включения реальных данных.

| Категория | Предлагаемый срок | Действие по истечении |
|---|---:|---|
| Фото обычного завершённого осмотра | 90 дней после завершения поездки | Удалить объект S3 и ссылку/метаданные фото |
| Фото, относящиеся к открытому замечанию | До закрытия замечания и ещё 90 дней | Удалить фото после закрытия и срока разбора |
| История поездки, осмотра без фото, парковки, принятия правил и аудит | 12 месяцев после возврата | Удалить либо необратимо обезличить, если оператор подтвердил отсутствие иной цели |
| Профиль доступа сотрудника | До окончания доступа | Отключить вход сразу после команды оператора; срок удаления идентификатора согласовать до пилота |
| Технические/security-логи | 30 дней | Удалить; не включать фото, токены, секреты или тела запросов |
| Резервные копии | Не более 30 дней, rolling | Автоматически исключить из ротации; восстановление копии не должно возвращать уже удалённые записи без повторной очистки |

Активная поездка, открытое замечание, расследуемый инцидент или документированный legal hold не удаляются автоматическим сроком; оператор назначает ответственного и дату пересмотра. Дополнительное хранение должно иметь записанную причину и срок следующей проверки.

## Ограничение текущей реализации

Текущий сервис не запускает автоматические purge/anonymize jobs по таблице выше. Это проект политики, а не гарантия удаления. До реализации и проверок удаления нельзя использовать указанные сроки как операционный контроль реальных персональных данных. Перед началом обработки оператору также требуется проверить применимые требования к уведомлению и информированию субъектов; см. [раздел Роскомнадзора для операторов](https://82.rkn.gov.ru/directions/pers/p15375/). Этот документ сам по себе не выполняет такую проверку.
