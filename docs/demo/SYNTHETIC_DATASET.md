# Синтетический набор MAX Fleet

Набор создан для демонстрации и автоматизированных проверок. На 30.09.2026 он включён в `services/data/fixtures/synthetic-seed.json`; отдельный VDS demo-контур проверен через авторизованный read-only Data API. Это не production и не проверка реального MAX.

## Состав БД после synthetic seed

- 10 машин `DEMO-001`…`DEMO-010` с вымышленными названиями моделей, пробегом 12 000–16 500 км, синтетическим уровнем топлива и учебными координатами в Москве.
- 4 синтетических пользователя: два тестовых водителя, один тестовый администратор и один заблокированный водитель. MAX ID в fixture фиктивные; не подключайте их к реальным аккаунтам.
- Одна версия демонстрационных правил и синтетическая запись MAX integration state.
- В fixture нет номеров телефона, реальных ФИО, настоящих регистрационных номеров или корпоративных контактов. Схема API пока не имеет полей для контакта сотрудника/ответственного.

## Фото для ручной проверки

В `docs/demo/vehicle-inspections/` есть 33 синтетических AI JPEG: по 8 ракурсов до и после для `DEMO-001` и `DEMO-003`, плюс один крупный план замечания. Это отдельные файлы для ручной загрузки через интерфейс; миграция не загружает их в БД или S3. `scripts/smoke.py` отдельно создаёт 16 минимальных 1×1 PNG в тестовой БД/S3 для проверки API/S3, а не для показа пользователям.

## Фактическое состояние отдельной VDS demo-базы

30.09.2026 полный smoke через Python Data API, PostgreSQL и S3 создал одну завершённую синтетическую поездку: 8 фото до, 8 после, ручное место `manual_map`, статус возврата `completed`, сохранённый предыдущий осмотр и событие уведомления. После сценария авторизованное чтение через Python API подтвердило contract 1.13, 10 машин (все доступны), 4 синтетических сотрудника, одну завершённую поездку и действующие правила. SQL напрямую не использовался. Это постоянные данные отдельного `max-fleet-demo` volume; повторный smoke там создаст дополнительную поездку, поэтому для повтора используйте новый Compose project.

Проверенная поездка использует 1×1 PNG из API smoke и не является визуальным демо. 33 AI JPEG выше по-прежнему нужно загружать отдельно при ручной проверке фотоэкрана. Контур привязан к loopback; он не является публичной демо-средой.

## Ограничения и безопасный запуск

- В production запрещён `SEED_SYNTHETIC=1`; для production установлен `SEED_SYNTHETIC=0`.
- Synthetic seed идемпотентно добавляет отсутствующие базовые записи, но не очищает БД, не создаёт историю поездок и не перезаписывает уже существующую версию правил.
- Для чистого теста используйте отдельный новый Compose project и изолированные secrets/volumes; никогда не направляйте synthetic seed на production.
- Фактически проверенный demo Data API: contract 1.13, 10 машин, 4 пользователя, одна завершённая поездка, правила доступны. `scripts/smoke.py` приложил 16 тестовых PNG к осмотрам через API/S3; это не загрузка 33 AI JPEG и не проверка настоящего MAX.
